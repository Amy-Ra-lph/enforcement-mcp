enforcement-mcp — User Story Walkthrough

enforcement-mcp

Structured SELinux, fapolicyd, and MLS policy intelligence for LLM agents.
19 tools across 3 tiers. CVE containment + risk scoring. One MCP server.
The problem: When SELinux or fapolicyd blocks something, today's agents hit a wall. They can't parse AVC denials, can't query policy, and can't distinguish an SELinux block from a fapolicyd denial from a plain DAC permission issue.

enforcement-mcp gives agents the same structured access that experienced RHEL sysadmins rely on — but as JSON, through MCP, with no risk of misconfiguration.
User Story 1

"Why is httpd blocked from serving home directories?"

Agent asks
Scenario
A developer reports httpd returns 403 when serving /home/jsmith/public_html. The agent calls the composite troubleshoot tool to find the root cause.
diagnosis.troubleshoot
Input{ "symptom": "httpd can't serve /home/jsmith/public_html", "process": "httpd", "path": "/home/jsmith/public_html" }
enforcement-mcp returns
Output{ "root_cause": "selinux", "confidence": "high", "denials_found": [{ "source": "httpd_t", "target": "user_home_t", "permission": "read", "class": "file" }], "checked_clear": ["dac", "fapolicyd", "capabilities"], "suggested_fixes": [ {"fix": "setsebool -P httpd_enable_homedirs on", "scope": "narrow", "risk": 15}, {"fix": "restorecon -Rv /home/jsmith/public_html", "scope": "targeted", "risk": 5} ] }
Key design: proves the negative
checked_clear shows what was ruled out — DAC, fapolicyd, capabilities. When enforcement isn't the cause, the tool says so and suggests where else to look.

User Story 3

"Is this binary trusted by fapolicyd?"

Agent checks trust
Scenario
A custom-built binary at /opt/myapp/bin/worker can't execute. The agent checks whether fapolicyd trusts it before recommending any changes.
diagnosis.fapolicyd_trust_check
Input{ "path": "/opt/myapp/bin/worker" }
What the agent learns
The binary isn't from an RPM and hasn't been added to ancillary trust. fapolicyd will deny execution. The fix: add it to ancillary trust (Tier 3 manage tool) or verify the RPM that should provide it.
enforcement-mcp returns
Output{ "path": "/opt/myapp/bin/worker", "trusted": false, "reason": "not_in_trust_db", "rpm_owned": false, "ancillary_trust": false, "sha256": "a1b2c3d4...f8e9", "would_execute": false, "matching_rule": 10, "rule_decision": "deny_audit" }

User Story 5 — Phase 2

"Is our sshd policy blocking the CVE-2024-6387 exploit chain?"

Agent asks
Scenario
CVE-2024-6387 (regreSSHion) was just published. Before patching, the agent checks whether current SELinux policy already blocks the exploit chain mapped via ATT&CK techniques.
diagnosis.cve_exposure
Input{ "cve": "CVE-2024-6387" }
How it works
Fetches CVE data from the Red Hat Security Data API (direct, no auth). Maps the CWE to ATT&CK techniques, then checks sesearch for each required permission in the exploit chain.
enforcement-mcp returns
Output{ "cve": { "cve_id": "CVE-2024-6387", "severity": "important", "cvss3_score": 8.1 }, "exploit_chain": [ {"technique": "T1068 Priv Escalation", "blocked": true, "rule": "No allow: sshd_t → kernel_t"}, {"technique": "T1059.004 Shell Exec", "blocked": true, "rule": "No allow: sshd_t → shell_exec_t"}, {"technique": "T1078 Valid Accounts", "blocked": false, "rule": null} ], "containment_score": 66, "blocked_steps": 2, "total_steps": 3, "residual_risk": "medium" }
Containment: 66%
2 of 3 exploit steps blocked. sshd_t can read shadow_t (needed for auth), so credential access isn't fully blocked. The agent can now use manage.cve_contain to close the gap.
User Story 6 — Phase 2

"What's the risk of enabling httpd_enable_homedirs?"

Agent asks
Scenario
The agent wants to fix the httpd home directory denial by toggling httpd_enable_homedirs. Before doing it, it runs assess_risk to understand blast radius and reversibility.
manage.assess_risk
Input{ "change_type": "boolean", "name": "httpd_enable_homedirs", "value": true }
Mandatory pre-mutation gate
Every Tier 3 (manage) tool runs assess_risk as step 1. No mutation without a risk score. The agent can also call it directly for "what if" analysis.
enforcement-mcp returns
Output{ "risk_score": 18, "risk_level": "low", "blast_radius": { "rules_unlocked": 3, "domains_affected": ["httpd_t"] }, "attack_surface_delta": { "permissions_granted": [ "read", "getattr", "search"] }, "reversibility": { "method": "setsebool -P httpd_enable_homedirs off", "difficulty": "easy" }, "recommendation": "proceed" }
Risk scoring factors
Blast radius (1 type vs many) · Permission severity (read=low, exec=high) · Target sensitivity (tmp_t=low, shadow_t=critical) · Reversibility (boolean=easy, MLS root range=dangerous) · Lockout potential

Agent requests

Output{ "containment_needed": true, "gaps_found": 2, "options": [{ "strategy": "minimal", "module_name": "emcp_cve_2024_6387_minimal", "cil_content": "(block emcp_cve_2024_6387_minimal\n (deny sshd_t shadow_t (file (read))))", "effectiveness": 40, "operational_impact": "low", "risk_assessment": { "risk_score": 0, "risk_level": "low"} }, { "strategy": "full_lockdown", "module_name": "emcp_cve_2024_6387_lockdown", "effectiveness": 75, "operational_impact": "high", "risk_assessment": { "risk_score": 12, "risk_level": "low"} }] }

Options are ranked by risk. The agent presents them to the operator. After confirmation, manage.load_module applies the chosen CIL module. Tagged with the CVE ID for lifecycle tracking.

Architecture

🌐
SSH Proxy Mode
Zero-install diagnosis. Agent connects to any RHEL host via SSH. Runs standard CLI commands (ausearch, getsebool, fapolicyd-cli). No packages to install, no root required for Tier 1 tools.
📦
Container Sidecar Mode
Full management with identity. Runs as a container alongside the workload. RHHI base image (near-zero CVE). Enables Tier 3 mutating operations with per-call risk assessment.
⚙️
FastMCP + Paramiko
Built on FastMCP 2.x (Python MCP SDK) with async SSH backend via Paramiko. Pydantic 2.x models for all structured I/O. 144 tests against real RHEL 9.8 CLI fixtures.
🔍
CVE Data — Direct API
CVE intelligence via Red Hat Security Data API (Hydra, no auth). No internal tooling dependency. Optional Insights MCP for affected-host correlation on registered systems.
